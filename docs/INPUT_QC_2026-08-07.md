## False-positive ID discrepancy found and resolved

The v0.1 audit compared the first FASTA header token directly to GFF transcript
IDs. This produced provider-specific false positives, most visibly all 41,025
Brassica rapa proteins and 8,076 Arabidopsis halleri proteins being reported as
unmatched.

Inspection showed that Ensembl protein headers can use a protein-specific first
token while providing the true relationship explicitly in a later
`transcript:<ID>` field. Examples include `Bra021453.1-P` mapping to
`Bra021453.1`, and `g09593.t1.cds1` mapping to `g09593.t1`.

Input normalization v0.2 therefore:

- preserves the primary sequence identifier;
- parses and prefers explicit transcript relationships from FASTA metadata;
- records whether each relationship came from header evidence or a primary-ID
  fallback;
- restricts required CDS/protein cross-checks to transcripts marked
  protein-coding and/or carrying GFF CDS features.

After this change, every one of the 505,601 expected translation transcripts
has exactly one mapped protein and one mapped CDS across all ten bundles.

## Translation consistency refinement

Five bundles contained 2,052 CDS records whose length is not divisible by
three. Treating every such record as an error is inappropriate for partial
official models. Input normalization v0.3 compares the translated codon count
of each CDS with the corresponding peptide length, accounting for terminal stop
codons.

All 2,052 frame-remainder records are protein-length-consistent. They remain
visible as observations, but no longer trigger a warning. A genuine
CDS–protein length disagreement still triggers the quality gate.

## Interpretation and next gate

This result establishes format, hierarchy, coordinate, namespace, and
translation consistency for the selected inputs. It does not establish that
the biological gene models are correct. The next benchmark gate must inject
known structural errors and evaluate recovery without treating any provider
annotation as complete ground truth.
